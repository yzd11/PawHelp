# 接入业务数据

PawHelp 当前使用匿名会话和演示业务数据。本次不接真实平台、不重训模型。
以下是后续升级的接入步骤，不是已经完成的生产功能。

## 服务知识

将有使用权限的商品说明、FAQ、售后政策整理为 Markdown，通过知识库页面预览并导入。
导入会切块、生成向量并更新索引，不改变嵌入模型、聊天模型或分类器权重。
先核对有效期、适用商品和政策范围，再用独立问题集检查召回、引用和拒答表现。
数据分布变化后应重新评估证据门槛；不要照搬旧报告或直接降低阈值。

## 订单、物流与商品

当前订单读取集中于 `app/services/orders.py`，数据访问在
`app/repositories/orders.py`，模型工具在 `app/tools/business.py`。
未来的外部平台实现应在该调用位置替换数据访问，不让模型拼接数据库查询或任意 URL。

接入顺序：

1. 增加认证与服务端可信客户身份，建立平台客户 ID 映射。
2. 在隔离环境验证平台只读接口，明确订单/状态/金额/时间字段转换。
3. 关闭订单读取时的 `seed_demo` 初始化，保留独立的演示环境和显式测试标识。
4. 替换模拟商品库存及 MCP 售后进度，未配置的能力返回不可用，不回退成随机数据。
5. 验证订单归属、超时、重试、权限不足和不存在等错误路径，再考虑写操作。

不能把 `is_demo` 改成 false 就视为完成接入；当前 MCP 售后实现和商品库存仍是模拟逻辑。
不要直接将真实订单导入当前匿名会话库后对外开放。

## 售后与人工坐席

本地退款申请表仅登记申请，不执行退款。真实业务必须接入售后系统，增加确认、
幂等键、审计、回调验证及状态同步。人工转接演示不连接真人；接入坐席系统需要
独立的连接、排队与会话交接流程。以上不通过微调模型实现。

## 飞轮与主题分类

真实问题取得授权并脱敏后，才可进入问题池；现有 17 类分类器可先旁路批量推理，
无需先重训。抽样复核真实数据，检查长尾类目、多标签漏标与领域漂移；根据错例
决定是否补数据和重新训练。主题分类不替代知识审核，也不直接发布服务政策。

真实语料、日志与权重默认留在本机，不随源码发布。调用外部模型需单独确认数据
目的地和使用范围，不能把本地试验的历史授权当成其他使用者的许可。
